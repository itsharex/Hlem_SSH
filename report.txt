SSH CONNECTION STATUS COMMUNICATION REPORT
==========================================

1. HOW FRONTEND DETECTS CONNECTION DROPS
=========================================

The frontend uses Tauri event listeners (pub/sub pattern) to detect connection status changes.

Event Setup (App.tsx, lines 177-213):
- remoteApi.onSshStatus(handleSshStatus)
- remoteApi.onSftpChanged(handleSftpChanged)
- remoteApi.onTerminalOutput(handleTerminalOutput)
- remoteApi.onTerminalClosed(handleTerminalClosed)
- Plus transfer, telemetry, and forward status listeners

When connection drops, backend emits "ssh://status" event with status="disconnected"
This triggers handleSshStatus handler which updates session state:
- state: "disconnected"
- connectionId: null
- terminalId: null
- sftpId: null (critical - FileManager becomes disabled)
- telemetryJobId: null
- files: [] (clears file listing)
- telemetry: empty object

3. CONNECTION TABS AND CONTEXT
===============================

Tab Management (App.tsx, lines 128-135):
- openSessionIds: array of session IDs that have open tabs
- activeSessionId: currently active tab
- openSessions: computed from openSessionIds + sessions array
- activeSession: computed from activeSessionId + openSessions

Tab Operations:
- Open tab: activateSession(id) adds to openSessionIds
- Close tab: closeSession(id) removes from openSessionIds
- Switch tab: setActiveSessionId(id)

Connection Lifecycle (App.tsx, lines 969-1091):
1. User clicks Connect
2. connectSession() called
3. remoteApi.connect(sessionId) returns connectionId
4. handleSshStatus updates state to "connected"
5. Terminal opens in background (terminalId set)
6. SFTP opens in background (sftpId set)
7. FileManager becomes enabled when sftpId is available


4. sftpId USAGE AND ACQUISITION
================================

How sftpId is Obtained:

Step 1: SSH connection established
  connection = await remoteApi.connect(session.id)
  connectionId = connection.connectionId

Step 2: SFTP channel opened
  sftp = await remoteApi.openSftp(connectionId)
  Returns: { sftpId: string, connectionId: string, openedAt: string }

Step 3: Stored in session state
  updateSession(session.id, (item) => ({
    ...item,
    sftpId: sftp.sftpId,
  }))

sftpId in FileManager.tsx (line 227):
  const canUseFiles = session.state === "connected" && Boolean(session.sftpId)

Usage Pattern:
  const sftpId = session.sftpId
  await remoteApi.listFiles(sftpId, path)
  await remoteApi.mkdir(sftpId, path)
  await remoteApi.upload(sftpId, localPath, remotePath, ...)
  await remoteApi.download(sftpId, remotePath, localPath, ...)

Passed via Props (App.tsx, line 1553):
  <FileManager
    session={activeSession}  // Contains sftpId
    onPathChange={...}
    onRefresh={...}
    onFileOperation={...}
    onUploadFiles={...}
  />

Transfer Target Tracking (App.tsx, lines 700-705):
  Maps sftpId to sessionId for transfer history persistence
  Used to recover session context when transfers complete


5. EVENT LISTENERS FOR DISCONNECT/CLOSE EVENTS
===============================================

SSH Status Listener:
- Event: "ssh://status"
- Handler: handleSshStatus (App.tsx, lines 829-852)
- Payload: ConnectionInfo { connectionId, sessionId, host, port, username, status, connectedAt }
- Action: Updates session state based on status value

Terminal Closed Listener:
- Event: "terminal://closed"
- Handler: handleTerminalClosed (App.tsx, lines 928-945)
- Payload: TerminalClosedEvent { terminalId }
- Action: Clears terminalId, adds "终端通道已关闭" message to terminal

SFTP Changed Listener:
- Event: "sftp://changed"
- Handler: handleSftpChanged (App.tsx, lines 854-859)
- Payload: SftpChangedEvent { sftpId, path }
- Action: Refreshes file listing for affected sessions

Manual Disconnect Flow (App.tsx, lines 581-604):
  async function teardownSession(session: RemoteSession) {
    if (!session.connectionId) return
    try {
      await remoteApi.disconnect(session.connectionId)
      updateSession(session.id, (item) => ({
        ...item,
        state: "disconnected",
        connectionId: null,
        terminalId: null,
        sftpId: null,
        telemetryJobId: null,
        files: [],
        telemetry: createEmptyTelemetry(item.host),
        terminal: [...item.terminal, createTerminalEntry("system", "连接已断开")],
      }))
    } catch (error) {
      appendTerminal(session.id, "error", formatSessionError(error, session))
    }
  }


6. DATA FLOW ON CONNECTION DROP
================================

Backend emits ssh://status event
    ↓
remoteApi.onSshStatus listener triggered
    ↓
handleSshStatus handler called with { status: "disconnected", sessionId, ... }
    ↓
setSessions updates RemoteSession:
  - state: "disconnected"
  - connectionId: null
  - terminalId: null
  - sftpId: null ← FileManager detects this
  - files: []
    ↓
FileManager re-renders:
  - canUseFiles = false (because sftpId is null)
  - File operations disabled
  - Tree view shows "SFTP 未连接"
    ↓
User sees disconnected state in UI
